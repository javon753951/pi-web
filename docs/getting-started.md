## 1. 概念简介：先认识这台"机器"的三个角色

可以把整个项目想象成一家小公司：

| 角色 | 通俗比喻 | 在代码里的名字 |
|---|---|---|
| **浏览器页面** | 前台接待区，你在这里下单、看结果 | `web/`（React 前端） |
| **网关** | 前台管家：接单、记账、安排员工干活 | `server/`（Node + Fastify 网关） |
| **引擎** | 真正干活的员工：会读文件、写文件、跑命令、用大模型思考 | `pi`（Pi Agent 引擎） |

**它们怎么配合**：你在网页上说话 → 管家（网关）把话转给一名员工（pi）→ 员工干完活把结果交回管家 → 管家转达给你。这个"转达"有两条线：

- **REST 接口**：像写信。你说一句，管家回一封信。适合"查列表、建会话、传文件"这类一次性的事情。
- **WebSocket 连接**：像打电话。线路一直通着，员工干活的每一步进展（思考、工具调用、每个字）都实时传给你。适合"聊天对话"这种连续的事情。

### 1.1 一个最重要的词：会话（Session）

**会话 = 一次完整的聊天 + 一张专属办公桌。**

每当你点"新建会话"，管家就会：
1. 在账本里登记一条记录（存在 SQLite 数据库里）；
2. 划出一张专属办公桌 —— 一个独立文件夹，叫**工作区（Workspace）**，路径是 `data/workspaces/<会话ID>/`；
3. 雇一名员工 —— 启动一个 `pi` 程序进程，让他在那张办公桌上干活。

所以记住一句话：**一个会话 = 一条聊天记录 + 一个文件夹 + 一个 pi 进程**。会话之间互不干扰，A 会话的文件 B 会话看不到（现在如此，MVP 及以后会更严格地保证这一点）。

### 1.2 术语表（遇到不认识的词就回来查）

| 术语 | 一句话解释 |
|---|---|
| **大模型（LLM）** | 会"思考"和写字的 AI 大脑，比如 DeepSeek。pi 靠它来理解你的要求和组织回答。 |
| **Agent（智能体）** | 比"聊天机器人"更进一步：它不只是回答，还会自己决定"接下来该读哪个文件、跑哪条命令"，一步一步把任务做完。pi 就是一个 Agent。 |
| **进程 / 子进程** | 正在运行的一份程序。网关启动 pi 来干活，这个被启动的 pi 就是网关的"子进程"（下级员工）。 |
| **工作区（Workspace）** | 每个会话的专属文件夹。Agent 读写文件都在这里进行，不让它乱翻别人的桌子。 |
| **产物（Artifact）** | Agent 干活过程中"写出来/改出来"的文件。系统会自动记录，你可以在右栏"产物"里看到。 |
| **Token（钥匙）** | 一串秘密字符，用来证明"这个请求是自家人发的"。网关只认钥匙，谁拿钥匙谁就能进门。 |
| **SQLite** | 一种数据库，整个数据库就是一个文件，像一本程序能读写的账本。项目用它记会话、设置、产物等"元数据"（描述数据的数据）。 |
| **沙箱（Sandbox）** | 给 Agent 划的"带围栏的游乐场"：它只能在围栏里玩耍（读写被允许的文件），够不着外面的东西。现在的围栏还比较矮（见 3.2），MVP 会逐步加高。 |
| **多租户（Multi-tenant）** | 一套系统同时服务很多互不相干的"客户"（租户），比如 A 公司、B 公司各用各的，彼此完全看不见。可以想象成一栋大楼，每家公司占几间房，房门各有各的锁。 |
| **配额（Quota）** | 给每个租户/用户限定的"用量上限"，比如最多存 5GB 文件、最多同时开 3 个会话。防止一个人把资源全吃光。 |
| **空闲回收** | 员工没事干太久就让他"下班"（停掉进程、释放内存）；你下次一说话，他立刻被叫回来上班。 |
| **冷启动** | 从零把 pi 进程拉起来的过程。因为要加载一堆扩展，需要几秒到十几秒。这就是你新建会话后看到"启动中…"的原因。 |
| **Docker / 容器** | 把整个程序连带它需要的所有环境，打包成一个"标准集装箱"，在任何机器上都能原样运行。项目提供了现成的集装箱（`docker/`）。 |

## 2. 主要功能与流程说明

### 2.1 现在的整体结构（单用户演示版）✅

```
你（浏览器）
  │  ① 发消息 / 收消息（REST + WebSocket，带钥匙）
  ▼
管家（网关 :8787）──账本（SQLite 文件）
  │  ② 按会话转达指令、盯着进程死活
  ▼
员工 × N（pi 进程，每会话一个，在各自的办公桌上干活）
```

**一个会话从生到死的完整流程**：

1. **新建**：点左栏"新建会话"。网关立即在账本登记，状态为"启动中…"，然后**在后台**慢慢拉起 pi 进程（不让你干等）。这是为什么新建后可以马上继续操作页面。
2. **启动**：pi 进程加载你机器上的全局配置（模型、密钥、已装扩展等）。冷启动通常要 **5~15 秒**。启动成功后状态变成"运行中"。
3. **对话**：你发一条消息 → 网关通过 WebSocket 把消息转给 pi → pi 用大模型思考、按需调用工具（读文件/写文件/跑命令）→ 每一步进展和每个字都实时流回页面。pi 如果写到文件，网关顺手把该文件记成"产物"。
4. **中止**：点输入框旁的"停止"，是让 pi **中止当前这次生成**（员工停下手里这单），进程本身还活着。
5. **崩溃**：如果 pi 进程意外退出（比如某个扩展加载失败），网关会察觉，状态变成"已崩溃"，左栏条目变红，悬停可展开"黑窗口"看错误详情。
6. **重新拉起**：崩溃条目悬停出现"重新拉起"按钮，点它网关会重新雇一名员工（重启进程），聊天记录还在（记录存在 JSONL 文件里）。
7. **删除**：悬停点垃圾桶图标，**再点一次确认**（防手滑）。这会删掉账本记录和整个工作区文件夹（JSONL 聊天记录文件保留）。进程也随之停止、内存释放。

> 💡 **目前没有"只暂停会话进程"的按钮**。想立刻释放内存，当前只能删除会话（会连带删掉工作区文件，注意先备份）。🚧 MVP 会加入"空闲自动回收"，这个问题就不存在了。

### 2.2 页面三个区域是干什么的 ✅

- **左栏**：会话列表。搜索、新建、删除、崩溃后重新拉起都在这里。条目上的小圆点颜色表示状态：启动中（黄）/运行中（绿）/已崩溃（红）/已停止（灰）。
- **中间**：聊天区。流式输出、折叠的思考过程、工具调用卡片（能看到员工用了哪个工具、传了什么参数）。输入框上方可选**模型**和**思考级别**。
- **右栏**：会话的工作区文件树（懒加载，自动忽略 node_modules）+ "产物"标签页（Agent 写出的文件清单，可打包下载）。

### 2.3 其他功能一句话速览 ✅

| 功能 | 在哪用 | 说明 |
|---|---|---|
| 文件上传 | 输入框 📎 / 拖拽 / 粘贴 | 传到当前会话工作区；`.zip` 自动解包，中文文件名不乱码，同名自动改名 |
| 打包下载 | 文件树勾选多个 → 打包；产物页一键打包 | 把工作区文件下载成 zip |
| 技能广场 | 顶部导航 | 搜索/安装 npm 上的 pi 扩展与技能。⚠️ **安装 = 在服务器上执行第三方代码**，见 3.2 |
| MCP 桥接 | 设置页 | 给 Agent 接外部工具服务（走 stdio 标准输入输出通信） |
| 模型/密钥 | 设置页 | 读 `~/.pi/agent` 里的模型配置，可直接写入新 API key（重启会话生效） |
| 局域网扫码 | 状态条二维码 | 手机扫码访问，链接自带钥匙 |
| 浏览器通知 | 状态条 🔔 | 任务完成/崩溃/等待审批时系统通知 |

## 3. 现在、MVP、最终形态：一张图看懂演进

### 3.1 现在：单用户演示版 ✅

**定位**：自己一个人用，装在自己电脑上。整个系统只有一把钥匙（自动生成在 `data/.token`，网页自动携带），所有会话共用同一套全局配置（同一个 `~/.pi/agent` 文件夹里的模型密钥和扩展）。

**为什么它还不能给很多人用**（三个最要命的点）：

1. **没有"你是谁"的概念**：任何人拿到那把唯一的钥匙，就能看/删所有会话。多个人用，等于所有人共用一把钥匙。
2. **东西互相能看见**：所有会话的员工都带着同一份"公司门禁卡"（共享 `~/.pi/agent`，含你的 API key 和配置），而且围栏很矮——员工技术上能读到别的会话的文件、甚至服务器的其他文件。熟人之间无所谓，陌生人之间不行。
3. **资源没有闸门**：每开一个会话就多一个常驻进程（粗略估算每个占几百 MB 内存），而且谁都能无限开、无限传文件。4GB 内存的机器大概同时养得起 3~5 个会话（粗略估算）。人一多，机器会被吃垮。

### 3.2 MVP 目标：多租户多用户版 🚧

在现有骨架上做加法，**不动引擎、不换数据库、不上 K8s**。核心就三条线：**身份、隔离、治理**。

```
你（浏览器，先登录）                    ┌────────────────────────────┐
  │  httpOnly Cookie（登录凭证）         │  网关（单实例）               │
  ▼                                    │  ├ 登录 + 用户/租户/审计      │
  REST / WS ──────────────────────────▶│  ├ 每请求校验"你是谁/哪个租户"│
                                       │  ├ 准入控制 + 空闲回收 + 配额 │
                                       │  └ EngineAdapter ─ pi 子进程 │
                                       └────────────┬───────────────┘
                                                    ▼
                                       pi 进程 × N（受控）
                                       办公桌: /data/tenants/<租户>/workspaces/<会话>
                                       门禁卡: /data/tenants/<租户>/users/<用户>/agent
```

对照 3.1 的三个问题，MVP 的解法：

| 问题 | MVP 解法（大白话） |
|---|---|
| 没有"你是谁" | **登录系统**：用户名 + 密码（scrypt 加密存储，登录后发一把有时效的钥匙，只存"钥匙的指纹"）。数据结构上从第一天就有"租户表、用户表、审计表"。 |
| 东西互相能看见 | **按租户/用户切目录 + 每请求检查**：每个用户有独立的门禁卡目录（自己的 API key、自己的扩展），每个租户的数据放在自己的文件夹里。所有接口先问"这个会话是你的吗？"再动手。 |
| 资源没有闸门 | **四道闸**：① 每用户同时最多 3 个会话（超了提示"稍后再试"）；② 会话 15 分钟没动静自动停掉、回来秒级唤醒（复用现有重启机制）；③ 租户磁盘配额（默认 5GB）；④ 对登录/建会话等接口限速。 |

另外两件 MVP 会收紧的事：
- **技能安装、改 API key、配 MCP 变成"管理员专属"**——因为安装技能等于在服务器上运行第三方代码，普通用户不能碰。
- **钥匙不再出现在网址里**（现在二维码链接带 token，网址会被代理服务器记日志，等于泄露钥匙）。

### 3.3 最终形态：更远的远景 🔮

- **每会话一个"单独集装箱"（沙箱容器）**：每个员工的游乐场是独立容器，限内存、限 CPU、只挂载自己的办公桌。容器停了内存立即释放。MVP 阶段先预留好换轨的接口（`EngineAdapter`），到时候只换实现、前端零改动。
- **管家可以分身**：网关做到"无状态"（状态都放数据库），就能跑多个副本，前面放负载均衡器——一台机器扛不住就加机器。
- **记忆层**：跨会话的长期记忆（参考 mem0 架构），会话 A 学到的东西，会话 B 能用上。文档 `docs/backend-decision.md` 有详细论证。
- **独立的数据库/对象存储、监控告警、计费系统**：这些等真有需要再加，MVP 刻意不做。

## 4. 常见问题解答（FAQ）

**Q1：为什么新建会话后，要等好几秒它才理我？**
这是"冷启动"：pi 进程要加载你机器上的全部扩展才上班，一般 5~15 秒。左栏显示"启动中…"就是还在加载，之后对话就流畅了。已运行的会话不会每次等。

**Q2：内存占用很高，能同时开几个会话？**
每个会话 = 一个常驻 pi 进程，粗略估算每个几百 MB。4GB 机器建议同时开 3~5 个。目前没有自动回收：想释放内存只能删除会话（会删工作区文件）。🚧 MVP 的"空闲回收"会解决这个问题。

**Q3：会话崩溃了怎么办？**
左栏该会话变红、显示"已崩溃"。鼠标悬停会话条目：点"重新拉起"重启进程（聊天记录还在）；点旁边的小箭头可展开黑窗口查看错误详情。多数崩溃是某个扩展缺依赖，去技能广场"已安装"里移除它再重启即可。

**Q4：我的文件存在哪里？两个会话之间共享文件吗？**
每个会话的文件都在 `data/workspaces/<会话ID>/`（自己的办公桌）。**会话之间不共享**。要跨会话用文件，从右栏打包下载，再上传到另一个会话。

**Q5：上传文件有大小限制吗？**
单个文件最大 **256MB**，`.zip` 会自动解包。目前没有"总量"限制（🚧 MVP 会加租户磁盘配额）。

**Q6：钥匙（Token）是什么？丢了怎么办？**
钥匙是一串自动生成的秘密字符，存在 `data/.token` 文件里。网页会自动带着它，你平时不用管。**不要**把带 token 的网址发给不信任的人。想换钥匙：删除 `data/.token` 再重启服务（会生成新的），或设置环境变量 `PI_WEB_TOKEN` 指定一个。

**Q7：为什么文档警告"不要暴露到公网"？**
现在的版本没有登录、没有用户隔离，pi 进程也没关进坚固的围栏里——拿到钥匙的人不但能看到你所有会话，还可能让 Agent 读到服务器上的其他文件。公网使用请务必放在可信网络里、前面加 HTTPS 反向代理。🚧 MVP 的多租户隔离上线后，公网部署才有安全基础。

**Q8：MVP 之后，用户 A 能看到用户 B 的会话吗？**
不能。每个请求都会校验"你是谁、属于哪个租户、这个会话是不是你的"；数据在磁盘上也按租户分目录存放（双保险）。管理员能看到本租户的概况（审计需要），但审计日志会记录谁在什么时候看了什么。

**Q9：为什么技能广场以后只有管理员能用？**
"安装技能"本质上是在服务器上**运行第三方代码**。单用户时风险自担，多用户时不能让一个普通用户装的东西影响所有人，所以收为管理员专属。

**Q10：会话开太多会怎样？**
现在：内存耗尽、机器变慢，极端情况下整个服务被拖垮。🚧 MVP 后：超出每人限额会被拒绝；闲置会话被自动回收；整个系统稳定运行。

## 5. 简单上手示例

### 5.1 第一次在本机跑起来（以 Windows 为例）

**准备工作**（只做一次）：
1. 安装 Node.js（22 或更新）：去 https://nodejs.org 下载 LTS 版安装。验证：命令行输入 `node -v` 能输出版本号。
2. 安装 pi 引擎：命令行输入 `pi --version`，若提示找不到命令，按 pi 官方说明全局安装（Docker 模式无需此步，集装箱里自带）。
3. 打开终端，进入项目文件夹：
   ```
   cd D:\projects\pi-web
   ```

**启动（开发模式）**：
```
npm install     # 第一次要装依赖，几分钟
npm run dev     # 同时启动网关(:8787)和前端开发服务器(:5188)
```
看到类似 `pi-web listening on ...` 的输出后，浏览器打开 **http://127.0.0.1:5188**。

### 5.2 创建会话并完成第一次对话

1. 页面左栏顶部点 **➕ 新建会话**（可先给它起个名字）。
2. 新条目出现，状态先是"启动中…"，约 5~15 秒后变成"运行中"。**期间不用干等**，可以先看看别的。
3. 在底部输入框输入一句话，回车，比如：
   ```
   你好，请先看看我的工作区里有什么文件，然后告诉我。
   ```
4. 观察回复流式出现；回复上方可以看到它调用了哪些工具（如 `list_files`）。想中止就点输入框旁的 **⏹ 停止**。

### 5.3 上传文件让它处理

1. 在输入框旁点 **📎** 选择文件（或直接把文件拖进聊天区、或 Ctrl+V 粘贴）。
2. 文件出现在右栏文件树里。传 `.zip` 会自动解包。
3. 接着对它说，例如：
   ```
   读一下 data.csv，统计每一列的空值数量，把结果写成 report.md
   ```
4. 完成后打开右栏"产物"标签：`report.md` 已自动记录，可预览或一键打包下载。

### 5.4 停止、重启、删除会话

| 想做什么 | 怎么做 |
|---|---|
| 中止当前这次生成 | 输入框旁"停止"按钮 |
| 崩溃后重启进程 | 悬停会话条目 → "重新拉起" |
| 删除会话（连带工作区文件） | 悬停会话条目 → 垃圾桶 → 2.5 秒内**再点一次**确认 |
| 删除前备份文件 | 右栏文件树勾选 → "打包下载" |

### 5.5 配置模型与 API key

1. 进入**设置页**。
2. 模型/密钥区会列出从 `~/.pi/agent` 读到的模型与供应商。
3. 要换 key：填入新 key 保存——它写入 `~/.pi/agent/auth.json`，**重启会话后生效**（去左栏点"重新拉起"即可）。
4. MCP 服务器同样在设置页配置，保存后重启会话生效。

### 5.6 用 Docker 跑（更像"正式部署"的方式）

```
npm run build                       # 先产出前端+后端成品
cd docker
docker compose up -d --build        # 构建并后台启动集装箱
```
打开 **http://127.0.0.1:8787** 即可使用。常用命令：

| 命令 | 作用 |
|---|---|
| `docker compose logs -f` | 看实时日志 |
| `docker compose down` | 停止并移除容器（数据在 `docker/data` 和 `pi-agent` 卷里，不会丢） |
| `docker compose up -d` | 再次启动（无需重新构建） |

> 提示：Docker 模式下，会话的办公桌在 `docker/data/workspaces/`，宿主机能直接翻看，排查问题方便。

### 5.7 🚧 预告：MVP 上线后的"管理员三步走"

以下是**规划中的样子**（当前代码还没有，接口名以最终实现为准）：

| 顺序 | 文档/代码 | 适合你了解 |
|---|---|---|
| 1 | `README.md` | 功能全览、配置项、排错（本文的"母文档"） |

| 5 | `web/src/pages/`、`web/src/components/` | 页面长什么样、前端怎么和网关说话 |

**代码地图（一句话版）**：
- `server/src/config.ts` 读环境变量、找 pi 在哪、生成钥匙
- `server/src/auth.ts` 校验钥匙
- `server/src/session-manager.ts` 会话的"生老病死"
- `server/src/rpc-bridge.ts` 网关和 pi 进程之间的"电话线"
- `server/src/workspace.ts` / `transfer.ts` 文件树、预览、上传下载
- `server/src/artifacts.ts` 产物追踪
- `server/src/marketplace/`、`mcp/` 技能广场、MCP 桥接
- `server/src/api/rest.ts`、`ws.ts` 对外接口（写信的、打电话的）

> 最后重申一句最容易混的点：**会话 ≠ 聊天记录**。会话 = 聊天记录 + 专属文件夹 + 一个 pi 进程。MVP 的"空闲回收"只是让进程下班，聊天记录和文件夹都原样保留——所以你能随时接着聊。
